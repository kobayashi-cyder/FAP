# FAP — Flexible Analog Predictive / Cognitive Architecture

FAPは、**小型・低RAM・高速応答を重視した実験的な認知アーキテクチャ**です。

巨大な言語モデルをそのまま小さくするのではなく、

* 会話
* 記憶
* 概念
* 仮説
* 検証
* 並列探索
* ガベージコレクション
* ページング
* 音声入出力

を、それぞれ役割の異なる「器官」として分けて組み合わせる設計を採用しています。

現在のFAPは、GPTのような大規模事前学習済み言語モデルそのものではありません。
むしろ、**小型の認知OS / 思考制御系**として発展させています。

---

## 1. 目的

FAPの主な目標は次の通りです。

1. 低RAM環境でも動く
2. 起動時に巨大な知識を常駐させない
3. 必要な情報だけを読み込む
4. 会話から必要なときだけ推論へ移る
5. 複数の仮説を同時に保持できる
6. 矛盾を消さずに検証対象として残す
7. 長時間利用してもメモリが膨張し続けない
8. 会話を自然かつ冗長にもできる
9. 将来的に外部モデルや追加器官を差し替え可能にする
10. FAP自体へ知識・会話能力を蒸留できる構造にする

---

## 2. 現在の基本構造

FAPの処理は概ね次の流れです。

```text
ユーザー入力
    ↓
会話状態の解析
    ↓
文脈・話題・意図の取得
    ↓
関連記憶の呼び出し
    ↓
概念グラフ参照
    ↓
仮説生成
    ↓
仮説競争
    ↓
複数枝の並列探索
    ↓
支持 / 矛盾 / 信頼度の比較
    ↓
計算資源の再配分
    ↓
最終統合
    ↓
自然会話化
    ↓
音声出力（任意）
    ↓
記憶整理 / GC
```

---

## 3. FAPの「器官」

### Conversation Organ

会話履歴、現在の話題、前の話題、寄り道、話題復帰、指示語などを扱います。

目的は、単純な一問一答ではなく、

```text
前の話
→ 今の入力
→ 必要なら少し脱線
→ 本題へ戻る
```

という会話の流れを保持することです。

---

### Retrieval Organ

現在の質問に関連する記憶を探します。

すべての記憶を毎回読むのではなく、関連度の高いものを優先します。

---

### Decomposition Organ

複雑な問題を小さなサブゴールへ分割します。

```text
大きな問題
↓
部分問題A
部分問題B
部分問題C
```

のように扱います。

---

### Verification Organ

事実・仮説・記憶の間にある、

* 支持
* 反例
* 矛盾
* 不確実性

を確認します。

矛盾した情報は即座に削除せず、競合状態として保持します。

---

### Integration Organ

分解された問題、証拠、仮説、矛盾をまとめて最終状態を作ります。

---

### Concept Graph

学習した概念をノードと関係として保持します。

例:

```text
FAP --uses--> Memory
FAP --has--> Hypothesis Engine
Water --is--> Liquid
```

同義語統合や重複圧縮も行います。

---

### Hypothesis Engine

既知の事実から、新しい候補を作ります。

例:

```text
A is B
B is C
---------
A is C ?
```

この結果は「事実」ではなく、あくまで仮説として保持されます。

---

### Hypothesis Competition

複数の仮説を比較します。

主な評価軸:

* 信頼度
* 支持数
* 矛盾数
* 新規性
* 検証コスト
* 情報価値

勝った仮説も自動的には事実化されません。

「次に検証する価値が高い候補」として扱われます。

---

### Parallel Search

複数仮説を別々の推論枝として探索します。

```text
仮説A ─→ 推論枝A
仮説B ─→ 推論枝B
仮説C ─→ 推論枝C
```

途中の成績を比較して、

```text
弱い枝 → 計算予算を減らす
強い枝 → 計算予算を増やす
```

という再配分を行います。

---

### Timeout Guard

考え続けて返答できなくなることを防ぎます。

現在の標準値:

```text
1枝            : 0.75 秒
並列探索全体   : 2.50 秒
1会話ターン     : 4.00 秒
```

時間切れでもエラー終了せず、

**その時点の最良結果を返す**

設計です。

---

## 4. メモリ管理

### 世代別GC

FAPでは単純な「古いものから削除」ではなく、
意味的なガベージコレクションを行います。

基準:

```text
70%  : 軽GC
85%  : 強GC
95%  : 緊急GC
```

処理順:

```text
重複統合
↓
圧縮
↓
低価値仮説削除
↓
低価値記憶削除
↓
緊急時のみ弱い事実を整理
```

重要なものは保護します。

* 支持された仮説
* 高信頼度の事実
* 頻繁に使われる概念
* 矛盾検証中の情報

---

### Hot / Cold Memory

V50以降では記憶をすべてRAMへ常駐させません。

```text
Hot Memory
    ↓
現在必要な記憶だけRAM

Cold Memory
    ↓
長期記憶はディスク
```

標準:

```text
Hot  : 64 items
Cold : 4096 items
Page-in : 最大8 items
```

質問が来たときに、関連する記憶だけをRAMへ戻します。

## 5. 会話機能

FAPは単純な短文応答だけでなく、長めの自然会話を行う方向へ拡張しています。

現在の会話モード:

```text
:brief
:normal
:rich
:verbose
```

標準は:

```text
:rich
```

です。

### Rich / Verbose の特徴

* 前の話題を拾う
* 理由を添える
* 具体例を入れる
* 少し寄り道する
* 本題へ戻る
* 同じ表現を繰り返しすぎない
* 曖昧な指示語を文脈から解釈する
* 訂正された場合は古い解釈を更新する

---

## 6. 音声

### Speech Output

Windows標準の `System.Speech` を使用します。

FAPの返答が完成した後に読み上げるため、
推論タイムアウトとは分離されています。

主なコマンド:

```text
:voice on
:voice off
:voices
:rate -10..10
:volume 0..100
:stop
:voicestat
```

日本語音声 `ja-JP` を優先します。

---

### Speech Input

V52ではプッシュ・トゥ・トーク方式の音声入力も追加されています。

```text
:listen
```

でマイク入力を開始します。

流れ:

```text
マイク
↓
音声認識
↓
テキスト化
↓
FAP
↓
推論
↓
返答
↓
音声出力
```

## 8. データセット蒸留

現在の次段階です。

5000件をそのままFAPへ入れるのではなく、

```text
5000会話
↓
共通パターン抽出
↓
重複除去
↓
会話ルール化
↓
小さな会話回路へ圧縮
↓
FAP本体へ組み込み
```

という不可逆圧縮を行います。

例:

```text
訂正
→ 古い解釈を弱める
→ 新しい解釈を優先

指示語
→ 直近文脈へリンク

長めの説明
→ 結論
→ 理由
→ 具体例
→ 補足
→ 本題へ復帰

曖昧な入力
→ 文脈から候補生成
→ 最も安全な候補を採用
```

これにより巨大な外部データセットを常時読む必要を減らします。

## 10. 起動

現在の統合Chatは次のランチャーを使います。

Windows:

```text
RUN_FAP_CHAT_LATEST.cmd
```

Debian / Linux / Android proot:

```bash
git pull --ff-only
chmod +x RUN_FAP_CHAT_LATEST.sh
./RUN_FAP_CHAT_LATEST.sh
```

Linuxランチャーは利用可能なローカルポートを選び、V87.39統合Chatを
バックグラウンド起動して、開くべきURLを表示します。Cコンパイラが
利用できればV87.38/V87.39のネイティブライブラリも自動ビルドします。

旧バージョンは引き続き `fap_vXX.py` / `RUN_VXX.bat` から直接起動できます。

---

## 11. 動作環境

統合Chatの対象:

```text
Windows 10 / 11
Debian / Linux
Android上のDebian/proot環境
Python 3
```

設計上、外部Pythonパッケージへの依存は極力減らしています。
V87.38/V87.39のC99ネイティブ部分はLinux/ARM64でもビルド可能な構成です。
ネイティブビルドが利用できない場合は既存のPythonフォールバックを使います。

音声機能の一部はWindowsの:

```text
System.Speech
PowerShell
```

を利用するため、Linuxでは同じ音声機能は保証されません。

## 12. 設計思想

FAPでは、

> 巨大なものを常に全部動かす

のではなく、

> 必要な器官だけを必要な瞬間に動かす

ことを重視しています。

これは、

```text
疎な活性
分業
局所処理
競争
抑制
再利用
圧縮
```

という考え方に近い設計です。

---

## 13. 現在の制約

FAPはまだ大規模言語モデルではありません。

特に不足しているもの:

* 大規模な世界知識
* 高品質な言語生成モデル
* 大量の事前学習
* 強い意味表現
* 長文の高度な意味理解
* GPT級の文章生成能力

そのため現在は、

```text
認知制御
+
小型会話器官
```

という段階です。
