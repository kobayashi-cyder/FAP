# V78 PREP — independent image provider evidence gate

Base/rollback anchor: `main@de4ed52e1b5c7d5a505f5ee5ca8d88110fa6bf15` (V77). This plan is non-binding and must be replaced if main moves before implementation.

## Scope
Small independent candidate: verify one concrete image renderer/provider adapter end-to-end. V77 records an independently verified adapter KEEP, but V78 must reproduce evidence from the actual implementation environment before claiming practical image generation. If no real backend/credentials/runtime is available, implement only the provider-neutral evidence/lifecycle boundary and DEFER generation claims.

## Expected files/interfaces
- `releases/v78/image_provider/adapter.*`: provider-neutral `ImageProvider.generate(request) -> ImageArtifact|ProviderError` boundary.
- `releases/v78/image_provider/verify.*`: independent invocation/decoder verifier; must not reuse adapter success flags as evidence.
- `releases/v78/image_provider/types.*`: bounded request/result metadata (provider id, MIME, dimensions, byte count, elapsed_ms, retained=false default).
- `releases/v78/tests/test_image_provider_negative.*`: failure/limit tests.
- `releases/v78/REPORT.md`: exact backend identity, commands, hashes/metrics, PASS/FAIL/DEFER; never store credentials or prompt/image payloads by default.

Names/extensions may follow repository conventions; interface semantics are the contract.

## Provider / renderer boundary
Core FAP owns request validation, budgets, cancellation and artifact metadata. The concrete adapter alone owns provider protocol/auth/transport. Independent verifier decodes returned bytes and checks MIME/signature/dimensions without trusting provider status. Provider-specific types must not leak into core. No sibling media branch is merged automatically.

## Negative tests
Missing/invalid credential; backend unavailable; timeout/cancel; HTTP/non-success or provider error; empty/truncated/non-image payload; MIME/signature mismatch; dimensions/payload over budget; unsupported format; malformed metadata; duplicate/retry behavior; secret leakage in logs; retained artifact when retention is disabled. All fail closed and must not be reported as generated images.

## Android implications
V78 does not add Android UI or storage permission requirements. A later Android consumer should accept decoded/verified artifacts through the neutral boundary, use app-private/cache storage by default, avoid broad media/storage permissions, and enforce lifecycle cancellation. Network permission belongs only to a concrete network-backed Android adapter.

## Privacy / retention defaults
No credentials in repo/logs. Prompt and generated bytes are ephemeral by default; `retained=false`. Persist only explicit opt-in artifacts. Reports record hashes, sizes, timings and redacted backend identity, not sensitive prompt/output content.

## Resource evidence
Record peak RSS delta, provider round-trip latency (p50 and max for bounded sample), decode latency, output byte size, temporary/persisted storage bytes, requested/actual dimensions. Promotion requires explicit budgets chosen from measured evidence rather than invented thresholds.

## Promotion evidence
KEEP only with: (1) concrete backend named, (2) adapter invoked independently from test harness, (3) returned artifact independently decoded, (4) content hash + dimensions + MIME recorded, (5) negative suite passes, (6) RAM/latency/storage measurements recorded, (7) no secret/payload retention by default. Otherwise DEFER.

## DEFER / REPLACE
DEFER real generation if backend, credential, runtime, decoder, or independent evidence is unavailable. REPLACE adapter if provider contract leaks into core, cannot be cancelled/bounded, requires unsafe retention, or repeatedly violates resource/error semantics. Keep video, STT/TTS, mic/output lifecycle, full-duplex, barge-in, echo cancellation, wake-word and streaming out of V78.
