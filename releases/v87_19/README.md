# FAP V87.19 — Autonomous Verified Media Skills

V87.19 turns image/video generation backends into FAP-managed autonomous skills.

The path is now:

`discover engine -> candidate skill -> generate real artifact -> observe actual file -> independent critic -> record verified outcome -> testing -> shadow -> active`

Generation engines:
- HTTPS-only endpoints;
- credentials referenced only by environment-variable name;
- synchronous image/video responses supported;
- bounded asynchronous job polling supported for video/image engines;
- async poll URLs are restricted to the configured engine origin;
- generated bytes are persisted atomically and SHA-256 digested before observation;
- image and video MIME types are checked against the requested media type.

Autonomous skill lifecycle:
- skills are named `media.generate.image:<engine>` or `media.generate.video:<engine>`;
- configured engines can be discovered from `FAP_MEDIA_ENGINES_JSON`;
- candidate engines may be exercised under the existing observed/critic gates;
- only distinct independently verified successful artifacts count toward promotion;
- candidate -> testing -> shadow -> active requires repeated verified success;
- duplicate output cannot manufacture promotion;
- repeatedly failing never-successful engines are rejected.

This release supplies the missing **Production Video Generator Adapter** contract as well as a generalized image adapter. A real configured provider can now return actual image/video bytes, including asynchronous video jobs, and FAP persists, observes, scores, routes, and promotes that generator autonomously.

No specific third-party model is bundled, and no external provider is represented as native FAP generation. Qwen is not used.
