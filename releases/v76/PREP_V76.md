# V76 candidate — Provider-neutral media adapter conformance

Status: preparation only; non-main.
Base/rollback anchor: main V75 `64619fbfe3967868a88085c4c4084ddcce4759ac`.

## Goal
Make the next smallest safe step toward practical image/audio capability without claiming a backend that has not been independently evidenced. V69 already defines provider-neutral image/STT/TTS boundaries; V76 adds a common adapter-conformance/probe layer that a real renderer/provider must pass before promotion.

## Expected files/interfaces
- `releases/v76/media_adapter/__init__.py`
- `releases/v76/media_adapter/conformance.py`
- `releases/v76/media_adapter/metrics.py`
- `releases/v76/test_media_adapter_conformance.py`
- interfaces: `ImageRendererAdapter.render(request)->artifact`, `STTAdapter.transcribe(pcm16)->text`, `TTSAdapter.synthesize(text)->audio`; capability metadata must identify kind, limits, timeout, retention policy and whether implementation is concrete or stub.

## Boundary
Core FAP owns request validation, time/resource budgets, artifact/transcript validation and metrics. Provider/renderer adapters own backend-specific invocation only. No provider credentials, model weights or provider SDK assumptions enter core contracts.

## Negative tests
Missing adapter; stub advertised as concrete; timeout; exception; empty artifact/transcript; wrong MIME/codec; oversized image/audio/text request; malformed PCM16; nondeterministic capability metadata; adapter attempts to persist input/output when retention is disabled. Fail closed and preserve existing V75 behavior.

## Android/host implications
This version does not acquire microphone permission or audio focus and does not play audio. Android adapters remain outside core until platform lifecycle evidence exists. File/content URI handling must be bounded and explicit; no implicit external storage writes.

## Privacy/retention defaults
Input prompts, PCM and generated artifacts are ephemeral by default; retention OFF. Metrics contain sizes/timings/status only, never prompt, transcript, raw audio or generated bytes. Secrets must be injected externally and never logged.

## Resource evidence required
Record peak RSS delta, wall latency, input/output byte counts and temporary-storage high-water mark per adapter probe. Promotion thresholds are evidence-derived rather than guessed; any unbounded growth blocks promotion.

## Promotion evidence
A concrete capability claim requires independent same-HEAD evidence from a real adapter: image output must decode and match declared MIME/dimensions; STT must return non-empty text from known speech fixture; TTS must produce decodable non-empty audio. Focused negative tests, compileall, and V69-V75 regressions must pass on the candidate HEAD. Without such evidence V76 may promote only as provider-neutral conformance infrastructure, with all generation/transcription/synthesis claims DEFERRED.

## DEFER / REPLACE
DEFER concrete image/STT/TTS claims when no independently evidenced backend is available. REPLACE an adapter when its contract changes, privacy behavior cannot satisfy retention-off, resource use is unbounded, or evidence cannot be reproduced. Full-duplex, barge-in, echo cancellation, wake-word and streaming are explicitly out of scope and remain separate later capabilities.

## Independence
No sibling media branch is merged automatically. V76 must remain useful as a small conformance layer even if any particular media adapter is abandoned.
